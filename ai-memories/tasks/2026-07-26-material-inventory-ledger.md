## Problem / 目标

为产品、行业、技术支持、案例、合作公司、新闻和公司页面建立可追踪的素材清单，明确来源、内容状态、公开许可、质量问题和替换需求。原始压缩包及解压大文件不得进入 Git，压缩包中的文件也不得因存在而被默认批准公开。

## 核心思路

- 以 `ai-memories/materials/2026-07-26-material-ledger.csv` 作为机器可读台账，以同目录当日总结记录审查结论和资料缺口。
- 先确认压缩包已完整下载，再解压至被 Git 忽略的 `ignored/materials/全资料/`；没有完整压缩包时不推测文件内容。
- 已有代码、旧站归档和 OSS 溯源表仅作为独立来源登记；公开状态与内容真实性分开判断。
- OSS 候选必须经过权利、隐私、客户名称、证书有效性和技术参数审查后才能从 `review-required` 改为 `approved`。

## 受影响的文件 / 模块

## Lessons Learned

- 素材的“来源可追踪”“内容已核实”和“允许公开”是三个独立判断，台账必须分别记录。
- 原始素材不可用时，可以先建立仓库来源基线和缺口清单，但不能把该基线冒充完整压缩包盘点。
