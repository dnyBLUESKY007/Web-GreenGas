# Task: 案例中心代码审查优化

- **日期**：2026-07-26
- **状态**：已完成
- **关联**：GitHub #9、`ai-memories/tasks/2026-07-26-case-center-list-detail.md`

## Problem / 目标

审查 GitHub #9 的案例中心实现，在不改变页面输出、交互和数据内容的前提下，减少项目数据在多个消费端的重复类型断言与查找逻辑，并加强既有数据不变量的自动化检查。

## 核心思路

建立单一的项目数据访问模块，由该模块统一导出有序项目列表、按 ID 查询和主图访问函数；主图访问函数显式检查每个案例至少有一张图片。保留 JSON 作为内容源和现有 DOM 渲染方式，仅替换重复导入、断言及线性查找。扩展契约测试以覆盖唯一 ID、关联 ID、必需多语言字段和图片元数据。

## 受影响的文件 / 模块

- `frontend/src/data/projects.ts` — 集中数据访问并检查非空图片不变量
- `frontend/src/components/case-carousel/`、`frontend/src/pages/` — 复用统一项目列表与 ID 查询
- `frontend/tests/case-center.test.mjs` — 加强案例数据契约

- [x] Step 3: 扩展案例数据契约测试并执行类型检查、测试及根路径/子路径构建。

## Lessons Learned

> 任务收尾时填写，供后续任务参考；重要结论应同步回 `ai-memories/memories/`。

- JSON 内容模型的类型断言应集中在单一数据边界；消费组件应复用该边界提供的列表、查询和不变量访问函数。
- 静态内容契约测试除字段存在性外，还应验证标识唯一性、引用完整性和外部来源主机，避免内容更新造成跨页面故障。
