## 外部阻塞

- **公开审批：** 35 个归档文件以及客户名称、肖像、车牌、政府/机场场地、第三方图片和技术参数须由责任人逐项批准或决定脱敏。
- **ISO 编号：** 甲方已于 2026-07-27 确认 `ISO140001` 为笔误，当前正式中英俄公开文案统一使用 `ISO14001`。该文案决定不等同于证书有效性确认。
- **OSS：** 需要上传并复核 25 个已登记案例/新闻 WebP；五张 Page Header 的登记路径与运行时命名也须先统一。
- **浏览器环境：** 当前 ARM 宿主缺少 Chromium 所需 NSS、GTK、GBM 等动态库，无法形成新的五宽度截图证据。
- **构建依赖审计：** `npm ci` 报告 `immutable` 与 `postcss` 两项可修复的高危传递性开发依赖告警；静态候选不部署这些包，但后续应单独评估并升级构建工具链。
- **生产授权：** GitHub #16 需要发布负责人明确审批。本候选没有修改服务器，也尚未执行生产部署。
- **EmailJS：** EmailJS 不属于本轮发布必需项，由 GitHub #17 单独处理。未配置时表单字段可见、提交按钮禁用，不绑定发送事件，也不显示虚假成功反馈。

## 审批结论

候选已经覆盖批准的信息架构和诚实内容状态，可供发布负责人审查。ISO 编号决定已于 2026-07-27 完成；其余建议把 25 个 OSS 404、公开许可矩阵和新一轮五宽度浏览器检查作为生产审批的显式条件；如批准带缺口发布，则必须接受页面保留示例、待替换和媒体不可用状态。无论采用哪种审批结论，生产动作均由独立 GitHub #16 执行。
